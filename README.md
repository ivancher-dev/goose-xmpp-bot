# Гусь — семейный XMPP-помощник

03.11.2026 владелец подтвердил: бот уже работает на основном аккаунте Гуся.
Текущая задача — [расширение пула погоды до пяти источников](docs/WEATHER_POOL.md)
после повторных отказов уведомлений. [Приёмка постоянной эксплуатации](docs/OPERATIONS_READINESS.md)
продолжается позднее; внешняя копия на домашний компьютер отложена владельцем.
Расписание отложено до публикации обновлённого сайта. Указания на отдельный
тестовый аккаунт в старых отчётах описывают условия тех этапов.

Версия 0.3.15 расширяет последовательный пул: Яндекс Погода, wttr.in, Open-Meteo,
MET Norway и 7Timer!. Четыре источника работают без ключей; Яндекс подключается
по бесплатному личному ключу с ограничением запросов. Прежний основной источник
сохраняется; заданный явно список резерва нужно дополнить самостоятельно.
Увеличен бюджет перебора; ожидание свободного места в очереди уведомлений
больше не расходует время получения прогноза. [Установка и ограничения](docs/WEATHER_POOL.md).

Версия 0.3.14 добавила [пул погоды и добровольные уведомления](docs/WEATHER_ALERTS.md).
При отказе Open-Meteo или wttr.in Гусь пробует второй сервис.

обновления и работу уведомлений. [Результаты и границы живой проверки](docs/WEATHER_ALERTS_REPORT.md).

Гусь принимает только разрешённых пользователей с доверенными устройствами и OMEMO.
Модель выключена по умолчанию; новый диалог начинается в manual. Включение модели
и auto — действия владельца. Приёмка постоянной эксплуатации и внешнее хранение
копий — текущий приоритет. Расписание ждёт публикации сайта; изображения — будущий этап.

Работают `!help`, `!ping`, `!admin status`, просмотр/изменение профилей, `!admin mode <bare_jid> [manual|auto]` и `!context clear`. На `!ping` Гусь отвечает `Га-Га-Га!`. `!echo` выключен по умолчанию и доступен только владельцу при явном включении. Права определяются нормализованным bare JID. Класс и `schedule_class_id` независимы; изменения профилей сохраняются при перезапуске.

Ручная отправка с другого устройства Гуся временно включает manual только этого диалога.
Если до перехвата был auto, он вернётся после настроенного интервала тишины владельца
(по умолчанию 60 секунд). Явная команда manual не получает таймер.
manual, очистка контекста и изменение профиля отменяют ожидающие ответы.
Ревизия и временный запрет отправки проверяются перед постановкой ответа в XMPP.
MAM восстанавливает память и ручную переписку, не запускает старые команды/API.
Сохранённый auto восстанавливается после успешной синхронизации от подтверждённой
позиции и при наличии Carbons. Временный сбой архива оставляет паузу до повтора;
утраченная позиция и первый запуск требуют явного auto. Явный manual сам не снимается. Сетевая задержка остаётся: для
гарантированного перехвата сначала включите manual и дождитесь подтверждения;
уже отправленное сообщение не отзывается.

Погода и новости по умолчанию отключены. После включения работают и в manual, без модели:
`!weather city Москва` сохраняет свой город, `!weather` показывает погоду,
`погода в Нью-Йорке` делает разовый запрос, `!weather tomorrow` даёт прогноз.
`!news` выводит до пяти свежих заголовков с датами и ссылками из заданных владельцем лент.
Первый источник погоды задаётся через `weather.provider`: `open_meteo` (по умолчанию),
`yandex`, `wttr`, `met_no` или `seven_timer`. Остальные используются последовательно
при отказе; [настройка пула](docs/WEATHER_POOL.md).
С версии 0.2.4 сводки оформлены в едином гусином стиле: русские описания, ветер в м/с,
местное время и источник. В 0.2.5 короткие вступления и концовки чередуются,
иногда сводка приходит без шутки. Можно попросить «Расскажи про погоду» или
«Какие последние новости?». Модель не придумывает и не пересказывает эти данные.
[Настройка и установка 0.2.5](docs/WEATHER_NEWS.md).

Команды принимаются напрямую и через проверенные входящие Carbons, если исходное сообщение получил другой клиент тестового аккаунта. Обе доставки проходят общую дедупликацию, allowlist и проверку устройства OMEMO. Исходящие копии и архив команды не запускают.

## Разработка и офлайн-проверки

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
.venv/bin/python -m pip install --no-build-isolation --no-deps -e .
.venv/bin/python -m pytest -q
bash -n scripts/install.sh scripts/doctor.sh
```

Тесты используют временные данные и подставной транспорт, запрещают исходящие соединения и не требуют секретов или root. Они включают реальное шифрование и повторное открытие хранилища, но не заменяют проверку с клиентами. Зависимости зафиксированы с SHA-256; при обычной установке lock-файлы не пересоздаются. Для намеренного обновления: `uv pip compile --generate-hashes requirements.in -o requirements.lock` и аналогично для `requirements-dev.in`, затем проверки API и тесты.

## Установка и запуск

**Обновление установленного Гуся одной командой и автозапуск:**
[docs/SAFE_UPDATES.md](docs/SAFE_UPDATES.md).

Базовая установка и доверие устройств: [docs/INSTALLATION.md](docs/INSTALLATION.md).
Настройка модели: [docs/INSTALLATION_STAGE2.md](docs/INSTALLATION_STAGE2.md).
**Переход с 0.2.5, свежая копия перед схемой 4, ручной перехват и восстановление:**
[docs/INSTALLATION_STAGE3.md](docs/INSTALLATION_STAGE3.md).

```bash
# Из чистого checkout заранее выбранного коммита; по умолчанию только подготовка файлов.
sudo bash scripts/install.sh
# После заполнения /etc/goose-xmpp-bot/config.toml и защищённого goose.env:
sudo systemctl enable --now goose-xmpp-bot.service
```

Установщик не изменяет Prosody/nginx/firewall. Код и virtualenv находятся в
`/opt/goose-xmpp-bot`, конфигурация — в `/etc/goose-xmpp-bot`, данные —
в `/var/lib/goose-xmpp-bot`. SQLite схемы 8 сохраняет прежние города, профили,
OMEMO, доверие, режимы и память; хранит позиции архива, хеши событий и отсечки
очистки, отдельные настройки языковых комментариев и статистику API без текстов запросов. При включённой модели
сохраняются входящие свободные сообщения,
ответы модели и расшифрованные ручные ответы своего диалога; при выключенной
новые тексты не сохраняются. `!context clear` удаляет память приложения,
срок хранения продолжает действовать. Рабочие данные не попадают в Git и логи.

TLS обязателен. Отправка и приём в этой версии ограничены `eu.siacs.conversations.axolotl` (legacy OMEMO). В slixmpp-omemo 2.2.0 не завершена обработка SCE для `urn:xmpp:omemo:2`; такое сообщение не вызывает открытый ответ. Слепое доверие отключено. Версии, ограничения и источники API приведены в [отчёте первого этапа](docs/STAGE1_REPORT.md).
