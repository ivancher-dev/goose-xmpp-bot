# Начало разработки в Codex

Репозиторий: https://github.com/ivancher-dev/goose-xmpp-bot .

## Порядок запуска

1. Подключить этот репозиторий к Codex и создать/выбрать среду проекта.
2. Убедиться, что выбрана ветка с текущими документами; начальная ветка — `main`.
3. Передать первую задачу текстом ниже. Работать отдельной веткой и представить изменения с результатами проверок.
4. Сначала проверить реализацию офлайн. Реальные аккаунты и секреты заполняются локально для живого теста на VDS; обычные тесты их не требуют.
5. После проверки подготовить выбранную версию для установки на тестовый аккаунт, выполнить клиентскую приёмку и записать результат. Следующий этап запускать отдельной задачей с учётом результатов.

Интерфейс облачной среды может меняться. Актуальная официальная инструкция: https://developers.openai.com/codex/cloud/ . В ней описаны подключение GitHub-репозитория, подготовка среды, запуск задачи, просмотр проверок и создание коммита/PR.

## Текст первой задачи

```text
Реализуй первый этап проекта «Гусь — семейный XMPP-помощник».

Сначала прочитай AGENTS.md, README.md, docs/SPEC.md,
docs/ROADMAP.md, docs/CONFIGURATION.md и подробное задание
docs/tasks/01-xmpp-foundation.md.

Выполни именно docs/tasks/01-xmpp-foundation.md: устанавливаемый
Python 3.12-сервис на Slixmpp для отдельного тестового XMPP-аккаунта,
проверяемая конфигурация, allowlist и права владельца, изменяемые
профили в SQLite, диагностические команды, постоянная идентичность
OMEMO, install.sh, doctor.sh, systemd и офлайн-проверки.

Клиенты владельца — Gajim и Conversations. Номер класса и
schedule_class_id — разные изменяемые настройки каждого пользователя.
Текущие 2-й и 7-й классы находятся только в примерах данных.
Изменения профиля должны сохраняться после перезапуска.

Не добавляй в этот этап LLM-генерацию, парсер расписания,
фотографии, рассылки или переключение на основной аккаунт Гуся.
Не меняй действующий Prosody и другие службы VDS в обычных тестах.

Сверь API выбранных версий Slixmpp и OMEMO-плагина с документацией,
зафиксируй совместимые зависимости. Выполни проверки без реальных
секретов и сети. Подготовь docs/TESTING_XMPP.md для живого теста;
не объявляй Gajim/Conversations проверенными без фактического теста.

Представь изменения отдельной веткой/PR. В итоговом отчёте укажи,
что реализовано, как проверено, что ещё требует живой проверки и
какие настройки владелец должен заполнить перед установкой.
```
