# Отчёт этапа 2

Дата: 26 октября 2026 года. Версия 0.2.0. Задание:
[02-model-memory.md](tasks/02-model-memory.md).

## Реализовано

- Отдельный HTTPS-адаптер OpenAI-compatible Chat Completions, HTTPX 0.28.1.
  Проверены сигнатуры установленной версии `AsyncClient.stream`, `Timeout`,
  `Limits`, `Response.aiter_bytes` и поведение через `MockTransport`.
  Официальный исходник API: [HTTPX 0.28.1](https://github.com/encode/httpx/tree/0.28.1/httpx).
  Адрес берётся только из конфигурации; редиректов и инструментов модели нет.
- Редактируемый внешний образ, актуальный профиль перед каждым запросом и
  отдельная история по нормализованному bare JID. Отдельные JID/идентификаторы
  расписания не добавляются в запрос модели; пользовательский текст не очищается
  от сведений, которые сам пользователь в нём написал.
- Явные manual/auto, запрос состояния режима, очистка своего контекста.
  Проверка владельца предшествует доступу к режимам и профилям.
- Задания упорядочены внутри диалога, HTTP не задерживает управляющую очередь.
  Пауза, очистка и смена профиля меняют ревизию и отменяют ожидающие задания.
  Перед синхронной постановкой ответа в XMPP-очередь режим и ревизия проверяются
  под блокировкой диалога. Уже поставленный ответ не отзывается.
- Сохранённый auto после подключения остаётся на паузе до нового подтверждения;
  manual и история сохраняются. Это ограничение до MAM-синхронизации этапа 3,
  защищающее от ответа без сведений о ручной переписке во время отсутствия бота.
- Общие ограничения HTTP-параллельности, попыток и частоты, конечный общий
  таймаут, предел тела ответа и текста, ограничение контекста/очередей/хранения.
  Уведомления об ошибках ограничены частотой для каждого диалога.
- Атомарная миграция SQLite 1 → 2, сохраняющая исходные таблицы с OMEMO,
  профилями и дедупликацией. Ошибка не оставляет частичную схему.
- Локальный doctor без API-запросов; явный `doctor --api` делает один запрос
  с пределом 16 выходных токенов, без повторов и вывода ответа/ключа.
- Установщик создаёт внешний образ только при отсутствии и сохраняет прежние
  настройки, ключи и данные. [Инструкция](INSTALLATION_STAGE2.md) содержит копию
  данных до миграции, настройку API и первичный пилот с владельцем.

## Проверки

В Python 3.12.14 прошли **197 офлайн-тестов**; реальные XMPP и API не использовались.
В зависимом slixmpp-omemo остаются 48 предупреждений DeprecationWarning.

После изменения шаблона дополнительно пройден существующий тест
`test_current_profile_and_editable_persona_applied_to_new_requests`: новый образ
читается для следующего запроса без перезапуска. Проверены внутренние ссылки,
TOML-примеры и размер UTF-8 файла образа в пределах 8192 байт.

Новые проверки охватывают разделение двух пользователей, порядок сообщений при
новом вопросе во время ожидания ответа, смену профиля/образа, окно UTF-8-контекста,
очистку и срок хранения. Проверены пауза/очистка/смена профиля при ответе API,
игнорирующем отмену, пауза во время шифрования, смена ревизии и запрет старому
обработчику забирать новую очередь. Пауза одного диалога не останавливает другой.

Интеграционный тест транспорта принимает команду manual во время ожидания модели.
Тест с настоящими ключами и XML API OMEMO шифрует кириллический ответ модели и
доказывает один запрос/ответ при обоих порядках direct/received-carbon.

HTTP MockTransport проверяет URL, Bearer и JSON-контракт, ошибки и ограниченные
повторы, отсутствие повтора после read timeout, общий таймаут, отмену, размер
и форму ответа, лимит фактических попыток. Обычный doctor не создаёт HTTP-клиент;
явная API-проверка проверена подставным транспортом без оплаты.

Прошли `pip check`, компиляция Python, `bash -n`, проверка локальных ссылок,
TOML и `git diff --check`. Старые версии зависимостей сохранены; новые HTTP-зависимости
зафиксированы с хешами.

Из чистого коммита дважды выполнен `install.sh --local` в отдельный временный каталог:
реальная установка зависимостей с проверкой хешей и сборка/установка wheel 0.2.0.
После первой установки изменены проверочные конфиг, env и внешний образ, созданы
профиль с изменённым классом, сохранённый режим, история и синтетическая запись OMEMO.
Повторная установка сохранила конфиг, env, образ и SQLite побайтно. После открытия
хранилища подтверждены профиль, второй профиль, режим, история и запись OMEMO.
Локальный doctor установленного wheel и его `pip check` прошли; сгенерированный
unit прошёл `systemd-analyze verify`. Настоящие systemd/XMPP/API при этом не запускались.

## Начало живого пилота

По результатам владельца от 26 октября 2026 года установка 0.2.0 выполнена
на VDS, сервис подключился с Carbons и MAM, диагностический ping получил ответ.
Локальный doctor подтвердил схему SQLite 2, целостность и привязку аккаунта.
Для отдельного профиля владельца включён auto; получен первый учебный ответ.

Подтверждён `doctor --api` с Yandex AI Studio, `aliceai-llm-flash/latest`
и Chat Completions через `https://llm.api.cloud.yandex.net/v1`.
В первом ответе обнаружены видимые LaTeX/Markdown-маркеры. В шаблон образа
добавлена инструкция писать обычным текстом. Следующий ответ не содержал
видимых маркеров; математические формулы после правки ещё не проверены.
По запросу владельца шаблон дополнен личностью правителя Гусинландии,
именами Гусик/Гусман, игровым хвастовством и шутливыми жалобами Папану.
Образ требует верного описания принципа изобретения и реального авторства
по уточнению. Проверено чтение обновлённого файла и его размещение в стандартном
окне контекста вместе с профилем и коротким пробным вопросом. Владелец подтвердил
появление новых черт после замены образа без перезапуска. В пробной байке
фактическое авторство раскрыто сразу, а описание нагрева оказалось неточным.
Уточнена граница между явно сказочной байкой и прямым фактологическим вопросом;
после подтверждённой команды очистки контекста модель снова раскрыла автора сразу.
В образ добавлен пример двух отдельных ходов диалога и сужено правило точности до учебных решений
и механизма изобретений, чтобы не смешивать их со сказочным авторством.
Явно указано дождаться нового сообщения собеседника перед раскрытием автора.
Короткая пара вопрос/ответ и уточнение с условным ответом 1200 байт помещаются
в стандартное окно контекста вместе с новым образом и пробным профилем.
Этот вариант ещё требует живой проверки. Команда очистки подтверждена владельцем;
удаление истории, отмена ожидающего ответа и изоляция живым тестом не доказаны.
Переписка, ключи и реальные идентификаторы пользователей в отчёт не включаются.

## Не проверено и ограничения

Пилот не завершён: память, manual, отмена, очистка, изоляция пользователей
и полная матрица клиентов ещё требуют живой проверки по
[TESTING_MODEL.md](TESTING_MODEL.md). Клиентские результаты версии 0.1.0
в [TESTING_XMPP.md](TESTING_XMPP.md) не считаются приёмкой генерации.
Денежный лимит у провайдера и нагрузка на VDS не проверены; другие службы
VDS во время обновления бота не изменялись.

HTTP-контракт требует совместимого Chat Completions с `max_tokens`. Совместимость
конкретных моделей, возрастные условия и обработка данных проверяются до пилота.
Оценка токенов по UTF-8 байтам с запасом консервативна и не заменяет измерение
токенизации выбранной модели. Лимит запросов не является денежным лимитом.

Ручные исходящие сообщения других устройств не попадают в контекст и не включают
паузу автоматически. MAM не загружается. Резюме истории не формируются; хранятся
ограниченные сообщения. Изображения, расписание, основной аккаунт, автоматическое
обновление и откат не входят в этап 2. Старый код 0.1.0 схему 2 не читает;
возврат только исходников не является безопасным откатом.
