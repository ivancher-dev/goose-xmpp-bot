# Отчёт этапа 3

27 октября 2026 года, версия 0.3.0. [Задание](tasks/03-owner-takeover.md),
[обновление и живая приёмка](INSTALLATION_STAGE3.md).

## Реализовано

- Ручной перехват по проверенным sent-carbon и собственным отправкам с другого
  resource. Проверяются внешние/внутренние адреса, тип, направление,
  единственность вложений, отсутствие вложенного архива/forwarded и служебных
  событий. Текст принимает только доверенное собственное OMEMO-устройство.
  При открытой/нерасшифрованной отправке включается пауза без импорта текста.
- Временный запрет отправки действует с допуска возможной ручной отправки.
  Он отменяет задания своего диалога и проверяется после ожиданий API,
  шифрования и БД. Другие диалоги продолжают работу. Переполнение очереди
  ручных событий закрывает сессию для восстановления вместо потери вмешательства.
- Постоянные alias по origin/stanza/server ID и ciphertext, с ограничением
  отправителем/получателем. Ответ сервиса регистрируется до send. Свои ответы
  и старые ручные копии не включают повторную паузу после явного auto.
- Схема 4 атомарно добавляет журнал хешей, позиции MAM и отсечки очистки/режима.
  Прежние профили, города, память, ключи, доверие и журнал доставок сохраняются.
  Ручная отправка, режим и запись истории фиксируются одной транзакцией.
- MAM загружается отдельно по разрешённым bare JID. Собственный ограниченный
  сборщик проверяет активный queryid, адрес архива, forwarded, время, ID/RSM,
  stable/complete и пределы. Неограниченный Collector `retrieve()` не используется.
- Первый запуск сохраняет последнюю позицию без импорта старого архива.
  После подтверждения владельцем успешное восстановление MAM и Carbons
  возобновляет прежний auto. Неполный архив оставляет паузу, manual не снимается.
- Восстановленные сообщения обновляют только свою память/ручной режим;
  команды, запросы модели и инструментов не выполняются. Память до очистки
  не возвращается; старый ручной ответ не отменяет более поздний явный auto.
- При подключении применяется режим синхронизации PyOMEMO, затем архив
  проверяется раз в минуту. Шифрование остаётся legacy, TLS и ручное доверие
  не ослаблены. Диагностический/управляющий клиент не запускает восстановление.

## Проверки

Общий прогон: **384 офлайн-теста** (67 новых), 180 предупреждений
DeprecationWarning из slixmpp-omemo. Среди них подделки Carbons/MAM,
оба порядка direct/sent-carbon, временная пауза до расшифровки, поздние
ответы при отмене API/шифрования, независимость диалогов, отсутствие повторной
паузы по старому событию и запрет отправки при переполнении очереди.

Настоящие OMEMO/Oldmemo-ключи проверяют два устройства одного аккаунта Гуся:
шифрование ручной отправки для собеседника и бота, расшифровку, ручное доверие,
единственный импорт, повтор с изменённым stanza ID и следующую архивную
отправку без генерации. Используется подставной PEP, сети и платных API нет.

XML-формы и подставной MAM проверяют исходную позицию, сохранение курсора при
открытии БД, возобновление auto, архивную ручную паузу только своего диалога,
удалённую позицию, недоступные расширения, поддельные результаты, неправильные
страницы/время, лимиты/таймауты, медленный архив одного собеседника, буфер live
во время запуска и отмену фоновой проверки при закрытии.

Миграция 3 → 4 проверена на синтетической прежней схеме с профилем, городом,
памятью, режимом, ключами и дедупликацией. Искусственная ошибка откатывает всю
миграцию; ошибка записи истории не оставляет ручной режим без события.
Проверены ограничение журнала при добавлении alias к дубликатам, хронология
ручной переписки и read-only doctor без изменения базы.

Проверены первый ручной ответ без прежнего вопроса, сохранение живых сообщений
при переводе часов назад и запрет отправки во время расшифровки ручной MAM-
отправки. Прошли `pip check`, компиляция Python, `bash -n`, внутренние ссылки,
TOML и синтаксис shell-примеров документации, `git diff --check`.

## API и источники

Проверены установленные Slixmpp **1.17.0**, slixmpp-omemo **2.2.0**, OMEMO
**2.1.0**. Используются публичные `make_iq_set`, `Iq.send`, MAM-form/RSM-stanza,
Callback/MatchXPath, `get_own_device_information`, `before_history_sync`,
`after_history_sync`, `encrypt_message` и `decrypt_message`.
В Slixmpp 1.17.0 `rsm['before']=True` создаёт пустой `<before/>`, а пустая
строка удаляет его; это проверено на реальном построителе XML в тестах.

- [XEP-0280: адреса и безопасность Carbons](https://xmpp.org/extensions/xep-0280.html).
- [XEP-0313: MAM, RSM, stable/complete, безопасность](https://xmpp.org/extensions/xep-0313.html).
- [XEP-0359: устойчивые идентификаторы](https://xmpp.org/extensions/xep-0359.html).
- [PyOMEMO API](https://py-omemo.readthedocs.io/en/latest/omemo/session_manager.html).
- [XML API slixmpp-omemo 2.2.0](https://github.com/Syndace/slixmpp-omemo/blob/b77bdd4cc16702a74bdaf23bdf543499f2f30515/slixmpp_omemo/xep_0384.py).

Спецификации сверены с исходниками XSF; контракты дополнительно проверены
на установленной версии зависимостей. Зависимости и lock-файлы не менялись.

## Что осталось проверить

Живой пилот **0.3.0 ещё не выполнялся**. Ранее на VDS работали Prosody 13.0.4,
Gajim 2.4.6 Windows и Conversations 2.20.4+free m149, но это не подтверждает
новые сценарии. Нужны ручной перехват и восстановление с обоими клиентами,
два параллельных диалога, bare/full-доставка и обрыв только сервиса.
Перезагрузка VDS не выполнялась и не требуется для первичной приёмки.

Сетевая задержка, политика хранения Prosody и недоступный старый OMEMO-архив
ограничивают восстановление. Гарантированный перехват требует явного manual
до ручного ответа. Архив не является полной резервной копией. Пределы,
условия подтверждения auto и ограничения отката описаны в инструкции.
