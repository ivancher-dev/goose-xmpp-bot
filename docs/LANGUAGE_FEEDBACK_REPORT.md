# Языковые комментарии 0.3.5–0.3.10: проверки

[Инструкция и ограничения](LANGUAGE_FEEDBACK.md),
[задание](tasks/03b-language-feedback.md).

Добавлена SQLite-таблица language_feedback с отдельными enabled/mode/max_notes
для каждого профиля. По умолчанию выключено, brief, максимум два замечания.
Миграция 4 → 5 транзакционная. Старые данные и ключи сохраняются, прямой откат
к старой схеме не выполняется. Новые зависимости не добавлены.

Право `!admin language` проверяет код до модели. Смена настройки увеличивает
ревизию и отменяет ожидающие ответы только этого диалога. Включение разбора
не меняет manual/auto. Модель не может сохранить настройки из текста вопроса.

Один обычный запрос сначала создаёт основной текст, затем необязательный JSON.
Служебная часть отделяется, проверяется и форматируется приложением. Нет
отдельного внешнего сервиса или API-вызова; выходной лимит не повышается.
Инструкция увеличивает входной контекст; замечания используют оставшийся
выходной объём. При нехватке места блок пропускается.

- В русском вопросе с ошибочной безударной гласной пришла поправка к нужному

- Следующее сообщение без этой просьбы снова получило исправление и правильное

- В английском вопросе лишнее -s у глагола исправлено верно. Пояснение было

  определяющее здесь условие: после do/does нужна начальная форма глагола.

Это подтверждает базовый русский сценарий владельца, а не безошибочность
проверки произвольного языка или сложного текста. Английское пояснение требует
доработки/дальнейшей оценки, язык пояснения не всегда следует языку сообщения.
Режим detailed, остальные пределы замечаний, живой отказ неадминистратору,
живое выключение одного диалога независимо от другого, смешанный текст,
защищённые цитаты и поздняя отмена языкового ответа в этом пилоте не проверялись;
они покрыты автоматическими проверками либо остаются в инструкции приёмки.
Последний диалог ребёнка с большим числом опечаток здесь повторно не проверялся.
