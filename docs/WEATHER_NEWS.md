# Погода и новости: версия 0.2.1

Это расширение [этапа 2](tasks/02a-weather-news.md), для отдельного тестового
XMPP-аккаунта. Расписание, чтение MAM и автоматический ручной перехват сюда
не входят. Погода и новости включаются отдельно, без ключа модели и без auto.
Живая доступность Open-Meteo и ленты РИА пока не подтверждена.

## Как пользоваться после установки

Отправляйте команды Гусю в личном чате с доверенным OMEMO:

| Сообщение | Результат |
| --- | --- |
| `!weather city Москва` | Сохранить свой город после поиска |
| `!weather city` | Показать свой сохранённый город |
| `!weather city #524901` | Выбрать город по GeoNames ID из ответа поиска |
| `!weather city clear` | Удалить свой сохранённый город |
| `!weather` / `погода` | Текущая погода и прогноз на сегодня в своём городе |
| `!weather tomorrow` / `погода завтра` | Прогноз на завтра в своём городе |
| `погода в Нью-Йорке` | Разовый запрос; свой город не меняется |
| `Гусик, какая погода завтра в Москве?` | Разовый прогноз на завтра |
| `!weather #524901` | Разовая погода по выбранному ID |
| `!news` / `новости` | До пяти свежих заголовков из настроенных лент |
| `!news ria` / `новости с ria.ru` | Только настроенный источник РИА |

Русские алиасы: `!погода`, `!новости`. Естественные формулировки распознаются
по ограниченным шаблонам, начиная с «погода», «какая погода», «новости»,
«покажи свежие новости»; допустимо обращение «Гусь/Гусик/Гусман».
Это не произвольный поиск в интернете и не инструмент внутри LLM.

Если найдено несколько одноимённых мест, Гусь показывает регион, страну и ID,
а прежний город сохраняет. Повторите команду с выбранным `#ID`. Для сложного
названия попробуйте именительный падеж. Геокодер не гарантирует понимание
всех русских падежей; три частые формы Москвы, Санкт-Петербурга и Нью-Йорка
нормализуются отдельно.

Город принадлежит нормализованному bare JID собеседника, сохраняется после
перезапуска и очистки контекста. Менять чужой город командой нельзя. Учебный
профиль не требуется. Город удаляется отдельной командой, а не `!context clear`.

Погода содержит дату, местный часовой пояс, температуру, ощущаемую температуру,
ветер и прогноз минимальной/максимальной температуры с вероятностью осадков.
Это данные модели прогноза Open-Meteo, не показания домашнего датчика.
Новости содержат только заголовок, дату публикации и ссылку на оригинал;
по умолчанию берутся записи за последние 48 часов, сортируются по дате.
Если свежих записей меньше пяти, показывается доступное число.

## Настройка

Добавьте в конец существующего `/etc/goose-xmpp-bot/config.toml` отсутствующие
разделы; существующие разделы редактируйте без дублирования:

```toml
[weather]
enabled = true

[news]
enabled = true
limit = 5
max_age_hours = 48

[news.sources.ria]
name = "РИА Новости"
url = "https://ria.ru/export/rss2/archive/index.xml"
```

По умолчанию обе возможности выключены. Старый конфиг 0.2.0 без этих разделов
также поддерживается. `news.limit`: 1–10; `max_age_hours`: 1–168. Можно задать
до восьми источников с уникальными ID из латинских букв, цифр, `_`, `-`,
начиная с буквы, до 32 символов. Имя источника — до 64 символов.
URL ленты — HTTPS, до 512 символов, без credentials, query и fragment.
Произвольные URL из чата не загружаются. Допустимые имена в команде:
ID, полное имя, первое слово имени или домен; неоднозначное имя нужно уточнить.

RSS 2.0 и Atom поддерживаются. Записи без проверяемой даты, старше заданного
срока, датированные более чем на пять минут вперёд или со ссылкой на чужой
домен пропускаются. Ссылки разрешены только на домен ленты и его поддомены;
текст статьи не загружается. RSS другого формата или с редиректом потребует
явного исправления настроенного источника. XML DTD и внешние сущности запрещены.

Open-Meteo используется через фиксированные адреса `api.open-meteo.com` и
`geocoding-api.open-meteo.com`. Для некоммерческого семейного использования
публичный API не требует ключа; для другого использования проверьте действующие
[условия Open-Meteo](https://open-meteo.com/en/terms).
Источники/атрибуция указаны в ответах: Open-Meteo, для поиска мест — GeoNames.
Геокодеру передаются искомые названия, API прогноза — координаты; JID, профиль
и переписка туда не передаются. Сохранённый город остаётся в локальной SQLite.
Источники видят исходящий IP сервера. Модель не получает эти запросы и результаты;
память LLM не используется для последующих уточнений погоды/новостей.

## Обновление на VDS

Выполняется на том сервере, где уже установлен бот. Prosody и другие сервисы
не останавливаются; перезагрузка VDS не нужна. Не выполняйте все шаги сразу:
после каждого проверьте ожидаемый результат.

### 1. Выбрать проверенный коммит

Из checkout, например `/root/goose-xmpp-bot`:

```bash
git status --short --branch
git fetch origin feat/weather-news
# COMMIT_SHA — полный SHA проверенного коммита из PR.
git switch --detach COMMIT_SHA
git log -1 --oneline
git status --short
```

Перед переключением не должно быть несохранённых изменений. Detached HEAD
допустим для установки фиксированной версии. Исходники не хранят рабочие ключи.

### 2. Остановить только бот и проверить свежую копию

Схема базы станет **3** при первом `run` или управлении устройствами новой версией.
До этого сохраните текущую схему 2 вместе с актуальными ключами, env и образом:

```bash
sudo systemctl stop goose-xmpp-bot.service
sudo install -d -m 0700 /var/backups/goose-xmpp-bot
goose_backup_dir=$(sudo mktemp -d /var/backups/goose-xmpp-bot/weather-news.XXXXXX)
sudo cp -a /var/lib/goose-xmpp-bot "$goose_backup_dir/data"
sudo cp -a /etc/goose-xmpp-bot "$goose_backup_dir/config"
sudo python3 - "$goose_backup_dir" <<'PY'
from pathlib import Path
import sqlite3, sys
root = Path(sys.argv[1])
with sqlite3.connect((root / 'data/goose.sqlite3').as_uri() + '?mode=ro', uri=True) as db:
    assert db.execute('PRAGMA quick_check').fetchone()[0] == 'ok'
for name in ('config.toml', 'goose.env', 'persona.md'):
    assert (root / 'config' / name).is_file(), name
print('Копия проверена:', root)
PY
```

Если образ хранится по собственному пути, сохраните и проверьте его отдельно.
Сохраните путь копии у себя; её содержимое не публикуйте и не помещайте в Git.
При ошибке копирования/проверки установку не продолжайте.

### 3. Установить и включить выбранные возможности

```bash
sudo bash scripts/install.sh
/opt/goose-xmpp-bot/venv/bin/goose-bot --version
sudo nano /etc/goose-xmpp-bot/config.toml
```

Ожидаемая версия: `0.2.1`. Установщик сохраняет старые конфиг, env, образ и
данные; настройки погоды/новостей добавляются вручную из примера выше.
Локальный `doctor` проверяет конфиг и целостность базы, но не мигрирует её,
не подключается к источникам и не делает платных запросов.

Текущий образ тоже сохраняется. Чтобы применить новый шаблон с театральным
«Дерзость!» и остальными согласованными чертами, после резервной копии можно
заменить образ шаблоном выбранного коммита:

```bash
sudo install -o root -g goose-xmpp-bot -m 0640 \
  config/persona.example.md /etc/goose-xmpp-bot/persona.md
```

Это заменит и ваши собственные правки образа: при необходимости перенесите
нужный абзац через редактор. Модуль погоды не требует замены образа.

### 4. Проверить конфиг, запустить бот и проверить миграцию

```bash
cd /opt/goose-xmpp-bot
sudo -u goose-xmpp-bot ./venv/bin/goose-bot doctor \
  --config /etc/goose-xmpp-bot/config.toml
sudo systemctl start goose-xmpp-bot.service
sudo systemctl is-active goose-xmpp-bot.service
sudo journalctl -u goose-xmpp-bot.service --since "2 minutes ago" -n 30 --no-pager
sudo -u goose-xmpp-bot ./venv/bin/goose-bot doctor \
  --config /etc/goose-xmpp-bot/config.toml
```

Ожидается `active`, `xmpp_ready`, затем схема 3 и целостность SQLite.
Отсутствие пароля в окружении обычного `sudo -u ... doctor` нормально:
сервис получает его из защищённого EnvironmentFile. Не добавляйте `--api`
ради проверки погоды/новостей. После подключения сохранённый auto модели
снова требует отдельного подтверждения владельца, как и в 0.2.0.

### 5. Живая приёмка в чате владельца

1. С OMEMO отправить `!ping`; получить ровно один `Га-Га-Га!`.
2. `!weather city Москва`. При нескольких результатах выбрать `#ID`, сверив
   название, регион и страну. Проверить `!weather city`, затем `!weather`.
3. `погода в Нью-Йорке`, затем `!weather city`: свой город не изменился.
4. `!weather tomorrow`: дата — завтра по часовому поясу выбранного города.
5. `!news ria`: не более пяти свежих заголовков с датами и кликабельными ссылками.
   Открыть одну ссылку и сверить заголовок/дату с оригиналом.
6. `!news unconfigured`: сообщение о неизвестном источнике, без его загрузки.
7. Проверить в Gajim и Conversations, затем повторить после перезапуска
   **только бота**: `sudo systemctl restart goose-xmpp-bot.service`.
   Город, ключи и доверие должны сохраниться. Проверку второго JID проводить
   отдельно, когда его доверенное устройство готово; его город должен быть пустым.

Недоступность источника не должна заменяться ответом модели или случайной
лентой. Проверить доступность можно с VDS без секретов, например для РИА:

```bash
curl --fail --silent --show-error \
  --max-time 15 --max-filesize 524288 --output /dev/null \
  https://ria.ru/export/rss2/archive/index.xml
```

Приложение редиректы не выполняет; для отдельного curl не используйте `-L`.
Не присылайте полный журнал/конфиг/ключи: достаточно кода ошибки и строк
`facts_failed`, `reply_queued`, `xmpp_ready` без переписки.

## Ограничения и возврат версии

На диалог допускается до четырёх заданий с учётом выполняемого, всего — до 32,
параллельно выполняются два. HTTP — до 60 попыток за скользящую минуту, без
автоматических повторов; таймаут сетевой операции 10 с, задания вместе с очередью
и шифрованием 30 с. Размер HTTP-ответа до 512 КиБ, кэш до 64 ответов на 5 минут,
просроченный кэш при ошибке не используется. HTTP-сжатие и редиректы отклоняются.
Переполненная очередь отбрасывает запрос с кодом в журнале; истёкшее задание
не отправляет запоздалое сообщение. Синхронизация часов на VDS важна для свежести.
Обычный `!ping` и административные команды не ждут погодного/новостного HTTP.

В manual явные запросы погоды/новостей доступны. Переход в manual и очистка
контекста отменяют ещё не отправленные задания этого диалога; уже поставленное
в XMPP сообщение отозвать нельзя. Свободные ответы модели подчиняются прежнему
режиму. Данные лент не попадают в модель и не могут выдать административные права.

Миграция 1/2 → 3 атомарно добавляет таблицу городов, сохраняет профили, историю,
режимы, OMEMO и дедупликацию. Старые версии 0.1.0/0.2.0 схему 3 отклоняют.
Возврат только исходников не является откатом. При проблеме остановите бот,
сохраните текущие данные и исправьте причину; нельзя без отдельного плана
подменять рабочую OMEMO-базу старой копией с устаревшими сессиями.

## Проверки разработки

В Python 3.12 прошёл общий набор тестов и проверки `pip check`, компиляции Python,
`bash -n`, `git diff --check`, внутренних ссылок и TOML-примеров.
Предупреждения DeprecationWarning исходят из slixmpp-omemo 2.2.0.

Автотесты работают без сети и секретов: HTTPX MockTransport, временная SQLite,
синтетические JID и данные источников. Проверяются изоляция городов, одноимённые
места и выбор ID, разовый запрос, даты/единицы/устаревшая погода; RSS/Atom,
сортировка/дедупликация, чужие ссылки, отсутствие даты, DTD, частичный отказ,
выключенные возможности, ошибки HTTP, размер ответа, кэш, очередь, отмена при
шифровании, остановка сервиса, доставка direct/received-carbon и команда manual
во время HTTP. Миграция с версии 2 сохраняет прежние данные.

API сверены с официальными исходниками:
[forecast OpenAPI](https://github.com/open-meteo/open-meteo/blob/main/openapi/forecast.yml),
[geocoding controller](https://github.com/open-meteo/geocoding-api/blob/main/Sources/App/GeocodingapiController.swift),
[defusedxml 0.7.1](https://pypi.org/project/defusedxml/0.7.1/).
В среде разработки запросы к Open-Meteo и РИА блокирует сетевой фильтр (`403`);
успех на реальных источниках не заявляется. URL РИА в конфиге — начальный
источник для живой проверки на VDS. Приёмка выше ещё не выполнена.
