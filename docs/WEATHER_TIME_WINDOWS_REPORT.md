# Время дождя и согласованные советы, 0.3.16

05.11.2026 владелец показал ответы Яндекс Погоды на сегодня и завтра.
Сегодня сводка сообщала «ясно» в текущем наблюдении и в 12:00, но заканчивалась
советом о зонте. [Исходная задача пула](tasks/02c-weather-provider-pool.md).

## Найденная причина

Адаптеры Яндекса, MET Norway и 7Timer! выбирали одну характеристику около полудня,
а температуру, ветер и признак дождя агрегировали по всем интервалам суток.
Любой дождливый интервал, в том числе закончившийся утром, мог вызвать совет
днём. Часы дождя не показывались. Ясное текущее наблюдение и дождь позже могут
быть совместимы, но по прежнему ответу читатель не мог понять причину совета.
Из скриншота нельзя установить, в какие именно часы исходный API сообщил дождь;
сырой ответ не сохранялся и у владельца не запрашивался.

## Исправление

- Сегодня используются интервалы, которые ещё не закончились. Закончившиеся
  исключены из температуры, ветра, вероятностей и советов. Начавшийся текущий
  интервал сохраняется, пока не закончится; на завтра остаётся весь доступный день.
- Период подписан «На оставшуюся часть дня». После полудня отдельное описание
  выбирается около времени запроса, без возврата к уже прошедшему полудню.
- При дожде добавляется строка с соответствующими прогнозными интервалами.
  Например, «Дождь в прогнозных интервалах: 18:00–21:00», даже если сейчас ясно.
  Смежные интервалы объединяются, сухие промежутки не закрашиваются; конец суток —
  24:00. Это разрешение исходных данных, а не точное обещание начала/конца дождя.
- Время наблюдения Яндекса переводится из `serverTime` в часовой пояс города.
  Ранее ответ с UTC-меткой мог отобразить часы UTC как местные.

Изменение относится к трём адаптерам с общей агрегацией. Open-Meteo и wttr.in
сохраняют прежние суточные показатели. Пул, лимиты, ключи, команды подписок,
manual, права, OMEMO, защита от повторов и схема SQLite 8 не менялись.
Новых полей API и зависимостей нет.

## Проверки

Полный офлайн-прогон: **864 теста прошли**, включая 20 новых регрессий.
`pip check`, компиляция Python, shell/TOML, внутренние ссылки изменённых
инструкций и `git diff --check` прошли.

Установленное обновление **0.3.15 → 0.3.16 прошло**:
`tests/integration/check_takeover_upgrade.py --baseline-ref 7e303637b05dc8e07fb5d2d2cc4f4594fbfab778`.
Код приложения проверен на `069cab7`; последующее дополнение отчёта его не меняет.
Временная лаборатория сохранила прежние строки БД, env/настройки/образ,
OMEMO-данные, статистику и таймер; схема 8 → 8. Копии до/после прошли пробное
восстановление, `pip check` установленной версии успешен. Из установленного пакета
проверены отсутствие совета по прошедшему утреннему дождю/холоду, местное время
Яндекса, явный вечерний дождливый интервал, прежнее уведомление в manual без
повтора и переход к пятому источнику. Все данные синтетические; systemd/XMPP
не запускались.
Регрессии воспроизводят: дождь только утром; ясно сейчас/в выбранный
час и дождь вечером; уже начавшийся интервал; точную границу его окончания;
раздельные дождливые периоды; завтра; последний час суток; повтор часа DST;
UTC-время Яндекса для Москвы, Калькутты и Нью-Йорка.

## Установка и живая приёмка

После слияния PR достаточно `sudo goose-update`: действующий ключ и погодные
настройки сохраняются. Новый ключ получать не нужно. С VDS в этой сессии
не подключались; живое поведение 0.3.16 пока не подтверждено.

Проверить `!weather`, `!weather tomorrow` и ближайшую плановую сводку.
При ясном текущем наблюдении и совете о зонте должен быть указан будущий или
ещё действующий дождливый интервал. Если таких интервалов нет, совета о зонте
для этих трёх источников быть не должно. Погода может меняться между запросами;
ожидать конкретные погодные условия для приёмки нельзя.
