# Языковые комментарии по собеседникам, 0.3.5–0.3.7

[Задание](tasks/03b-language-feedback.md), [проверки](LANGUAGE_FEEDBACK_REPORT.md).
По умолчанию функция выключена у всех. Настройки хранит SQLite, отдельно
по bare JID; менять их может только владелец из управляющего аккаунта.
TOML, ключ API и существующий внешний образ менять не нужно.

## Поведение

Гусь сначала отвечает на вопрос. Затем в том же зашифрованном сообщении может
добавить короткий гусиный комментарий: исходный фрагмент → исправление,
понятное правило и пример. По умолчанию не более двух замечаний, кратко.
Если уверенных замечаний нет, отдельного блока нет.

Например, на «Почему трава зилёная?» сначала нужен ответ о хлорофилле,
затем возможна заметка: «зилёная» → «зелёная»; проверим словом «зе́лень».
Примеры здесь синтетические. Нет счётчика общей грамотности, сравнения детей
или жалоб Папану из-за ошибок. Шутка — про самого гусиного редактора.

Модель анализирует язык текущего сообщения, включая английский и смешанный
текст; пояснения — на его языке или по явной просьбе собеседника. Код не заменяет
лингвистическую проверку и не гарантирует точность правил для любого языка.
Если модель не уверена в языке/норме, она должна пропустить блок.

В manual автоматического разбора нет. Команды погоды/новостей, статусы,
лайки, архив и повторные доставки его не запускают. Явная просьба проверить
чужую цитату остаётся обычным вопросом к модели, а не личной ошибкой ребёнка.

## Команды владельца

Отправлять Гусю из разрешённого управляющего аккаунта, заменив адреса на свои:

```text
!admin language pupil1@example.org
!admin language pupil1@example.org on
!admin language pupil1@example.org mode=brief
!admin language pupil1@example.org max_notes=2
!admin language pupil2@example.org off
```

Команда без последнего аргумента показывает текущие настройки.
`on`/`off` меняют включение; `mode=brief`/`mode=detailed` — длину пояснений;
`max_notes=1`…`max_notes=5` — верхнюю границу количества, не обязательное число.
Каждая команда меняет одно поле и сохраняет остальные. Подробный режим
допускает более длинное правило/пример, общий объём всё равно ограничен.

Настройки сохраняются при перезапуске и очистке контекста. Изменение настройки
отменяет ещё не отправленный ответ только этого собеседника; новое поведение
применяется к следующим вопросам. Оно не включает auto само по себе.
Для ребёнка без профиля сначала нужен обычный полный профиль.

Просьба «Сейчас без исправлений» или «Don't correct my writing» подавляет
необязательный блок этого сообщения, не выключая настройку навсегда.
Другие формулировки понимает модель; эти русские/английские варианты
дополнительно проверяет приложение.

## Как сохраняется основной ответ

Используется тот же Chat Completions-запрос с прежними ограничениями времени,
числа попыток и выходных токенов. Отдельный сервис проверки и дополнительный
запрос не добавлены. Инструкция и замечания могут увеличить число токенов
обычного запроса и его стоимость в рамках уже заданных лимитов.

Модель сначала пишет основной ответ, затем необязательные структурированные
метаданные. С 0.3.6 инструкция формата объединена с общими правилами в первом
system-сообщении. Она прямо просит проверять сообщение и возвращать
метаданные даже с пустым notes, если уверенных замечаний нет. Пустой блок в чат
не выводится. Приложение удаляет служебную часть и само оформляет проверенные
замечания. Обрезанный JSON, неопределённый язык, отсутствие правила, примера
или точного фрагмента не отнимают готовый основной ответ.

С 0.3.7 в тот же запрос передаётся нумерованная таблица слов только текущего
вопроса. Это данные сообщения, не инструкции. Модель указывает start/end —
номера первого и последнего слова включительно, начиная с 1. Исходный фрагмент
приложение извлекает из самого сообщения. Поэтому исправление не зависит
от точного копирования моделью ошибочно написанного слова из истории.
Вопрос в истории не меняется; номера и таблица в чат не выводятся.
Слова здесь — непробельные фрагменты с прилегающей пунктуацией; диапазон
сохраняет исходные пробелы. Слишком длинные и защищённые фрагменты пропускаются.

Прежний текстовый source также принимается для совместимости: предпочтителен
точный фрагмент, затем допускаются внешние кавычки, е/ё, регистр и пробелы
при однозначном сопоставлении. Показывается исходное написание из сообщения.
Отсутствующее или иначе написанное слово не угадывается; неоднозначность,
недопустимый диапазон и пересечение с защищённым текстом отбрасываются.
Проверка имён/чисел/отрицаний применяется к настоящему исходному фрагменту.

Итог — до 4096 символов; ради замечаний основной ответ не обрезается.
При сбое самого API готового ответа может не быть — остаётся обычная обработка
ошибки модели. Протокол не гарантирует полноту текста, который модель не создала.

Для инструкции можно сократить старую часть окна переписки, сохранив текущий
вопрос и ближайший обмен — обычно три сообщения. Если инструкция и они не помещаются, необязательный разбор
пропускается, а основной запрос использует обычное окно. В журнале виден только
фиксированный код `language_feedback_skipped reason=context_budget`.
В 0.3.6 инструкция сокращена с 2344 до 1347 UTF-8 байт; в 0.3.7 размер также
зависит от таблицы текущих слов. Бюджет 9000 проверен
с полным образом, правилами лайка и двумя недавними развёрнутыми ответами;
прежняя инструкция в таком же контексте не помещалась.

Диагностика: `language_feedback_requested` — инструкция передана модели;
`language_feedback_added notes=N` — замечания добавлены. Причины skipped:
`context_budget`, `missing_metadata`, `invalid_metadata`, `uncertain_language`,
`no_notes`, `filtered_notes`, `output_budget`, `opt_out`, `no_answer`.
`language_feedback_filtered` показывает только числа замечаний, отброшенных
по формату, изменению смысла/регистра, отсутствующему/защищённому фрагменту
или повтору. Ни фрагментов, ни JID, ни ответа API в этих строках нет.

Чужие/несуществующие фрагменты, цитаты в кавычках, code fences, inline-код,
URL, LaTeX-фрагменты и строки с явными метками «Условие задачи:», «Цитата:»,
«Код:» отбрасываются. Проверяются также повторные замечания и изменения
числовых значений, явных отрицаний и слов с заглавной буквы.
Это консервативные фильтры: некоторые полезные поправки, например изменение
регистра или имени, тоже будут пропущены. Они не доказывают сохранение смысла
произвольной фразы и не гарантируют распознавание всех цитат/условий.

Исходное сообщение в истории не переписывается. Видимый ответ с замечаниями
сохраняется в обычной истории своего диалога на прежний срок, отдельного
досье ошибок нет. Логи не содержат исходных фрагментов или правил.

## Обновление с 0.3.4–0.3.5 и приёмка

1. На VDS установить проверенный SHA версии 0.3.7 существующим обновлятором:

```bash
sudo goose-update --ref ПРОВЕРЕННЫЙ_SHA
```

Перед переключением создаётся копия; сначала пробуется миграция отдельного
клона. При переходе с 0.3.4 схема SQLite повышается 4 → 5; с 0.3.5/0.3.6 остаётся 5.
Ключи, доверие, профили, города, история,
режимы и настройки регулярного копирования сохраняются. Прежний auto
возвращается после полной проверки архива, намеренный manual остаётся.
Прямой откат на код 0.3.4 после миграции не поддерживается; обновлятор
не заменяет рабочую OMEMO-базу старым снимком.

2. Проверить свои настройки командой просмотра. Включить только один
пилотный диалог, оставить второй выключенным. Задать новые синтетические
вопросы, например «Почему трава зилёная?» и «Why I is here?». Нужны ответ
по существу и понятное уместное исправление; без служебного JSON в чате.
Проверить «Сейчас без исправлений», сообщение без ошибок и цитату/код.

3. Проверить права: обычный разрешённый аккаунт получает отказ на `!admin language`.
Проверить краткий/подробный режим, лимит, независимость второго диалога,
новый вопрос после перезапуска службы, сохранение manual и отсутствие
запоздалого разбора при ручном вмешательстве.

4. После обновления проверить `sudo goose-backup status`. Старую копию схемы 4
можно проверить `restore-test`: мигрирует только временный клон. Новые копии
содержат схему 5 и отдельные языковые настройки.

Живая точность Alice AI LLM Flash и показ в Gajim/Conversations ещё требуют
приёмки. Обычные тесты работают с подставной моделью и не доказывают, что
реальная модель всегда выберет верное правило или соблюдёт формат.
