# Задача: настраиваемые языковые комментарии

Статус: **реализовано в 0.3.5, исправления 0.3.6–0.3.10; учебное качество живой приёмки ещё не принято**.
Добавить необязательный доброжелательный разбор ошибок в сообщениях собеседника,
сохранив полноценный ответ на его вопрос. [Настройка и установка](../LANGUAGE_FEEDBACK.md),
[проверки и ограничения](../LANGUAGE_FEEDBACK_REPORT.md).

## Поведение

- Сначала ответить на исходный вопрос или уточнить неполное условие. После этого
  можно добавить короткий языковой блок. Разбор не сокращает необходимое решение
  и не заменяет ответ исправленным вариантом вопроса.
- Шутка направлена на гусиную занудность: «Га-Га-Га! На минутку включаю гусиного
  редактора…». Чередовать реплики; обходиться без оценок грамотности, сравнений
  детей, обидных ярлыков и жалоб Папану из-за ошибок.
- Для каждого замечания: исходный фрагмент, исправление, понятное правило
  и пример или проверочное слово. Если слово словарное, сказать об этом;
  проверочное слово и правило не выдумывать. Объяснение учитывает актуальный
  класс и стиль из профиля, без ветвлений по конкретным двум классам.
- Учитывать орфографию, пунктуацию, грамматику и синтаксис; стилистический
  совет отличать от ошибки. Не исправлять допустимые варианты и неуверенные случаи.
  По умолчанию показывать только несколько наиболее полезных замечаний.
- Число ошибок и распределение по категориям необязательны. Называть их только
  при уверенной проверке, без двойного счёта. Лучше «поправим одно место», чем
  уверенный, но неверный отчёт о пяти ошибках. При отсутствии замечаний блок не нужен.
- Не приписывать ребёнку ошибки из цитат, условия задачи, кода, URL, формул
  или чужого текста. Явная просьба проверить такой фрагмент меняет область
  проверки, но не делает его личной ошибкой собеседника. Учитывать намеренную
  шутку, разговорную запись и чатовые сокращения.
- Просьба «сейчас без исправлений» подавляет необязательный блок для текущего
  сообщения, сохраняя основной ответ. Полный разбор можно запросить отдельно.

## Языки

Определять язык по текущему анализируемому сообщению, а не по языку интерфейса
или общему русскому образу Гуся. Английский текст проверять по английским правилам,
русский — по русским. Для смешанного текста различать фрагменты и не переводить
их ради проверки. Короткий или неоднозначный текст не даёт основания угадывать
язык и уверенно объявлять ошибки.

Язык пояснений должен быть понятен ребёнку: по умолчанию учитывать язык его
сообщения и явную просьбу. Например, можно объяснить по-русски ошибку в английском,
сохранив английские примеры и правила. При недостаточной уверенности в языке
или норме пропустить комментарий; обычный ответ продолжает работать.

## Настройки и интеграция

- По умолчанию функция выключена. Владелец включает её отдельно для каждого
  нормализованного bare JID; настройки сохраняются между перезапусками.
- Настраиваются включение, краткий/подробный режим и предел замечаний.
  Реализовано: краткий режим, максимум два замечания по умолчанию; переключение
  brief/detailed, max_notes 1–5. Команда владельца `!admin language <bare_jid>`
  с on/off, mode=brief|detailed или max_notes=N. Язык определяет модель по тексту;
  отдельная настройка явного языка в 0.3.5 не добавлена.
- Права постоянных настроек проверяет приложение. Модель и текст ребёнка
  не выдают административных прав; настройки разных собеседников независимы.
- Протокол результата должен отделять основной ответ от необязательного разбора.
  При ошибке разбора, неподдерживаемом языке, нехватке времени или объёма
  отправляется основной ответ. Если для него нужен весь доступный объём,
  языковой блок пропускается. Не допускать ситуации «есть замечания, нет ответа».
- По возможности использовать тот же запрос к модели. Если понадобится отдельный
  запрос, обосновать стоимость и задержку, задать лимиты и независимый отказ.
  Новый внешний сервис проверки подключается только явно настроенным владельцем.
- Исходный текст сообщения в истории не переписывается. Исправление не меняет
  смысл вопроса, числа, имена, отрицания и условия задачи. Ошибки ребёнка
  не превращаются в постоянную оценку или отдельное досье по умолчанию.
- Сохраняются OMEMO, allowlist, ручное доверие, разделение диалогов и отмена
  по актуальной ревизии. В manual нет автоматических языковых ответов.
  Команды, статусы, реакции, архив и повторные доставки не запускают разбор.
  Реальные сообщения и их ошибки не попадают в Git и обычный журнал.

## Пример ожидаемого результата

Синтетический вопрос: «Почему трава зилёная?»

Сначала основной ответ: в листьях есть хлорофилл; он поглощает часть света,
а отражённый зелёный свет придаёт траве видимый цвет.

Затем короткий комментарий: «Га-Га-Га! На минутку включаю гусиного редактора:
“зилёная” → “зелёная”. Первую гласную проверим словом “зе́лень”: там “е”
под ударением». Это иллюстрация, а не обязательная одинаковая реплика.

## Приёмка

1. Включение у одного пользователя не влияет на другого; настройки переживают
   перезапуск. Выключенная функция сохраняет прежний режим общения.
2. Содержательный вопрос с ошибками получает полноценный ответ и ограниченный
   разбор. Ошибка или обрезание языкового блока не теряет основной ответ.
3. Проверены синтетические русский, английский, смешанный и неоднозначный текст,
   цитаты, код, формулы, сокращения и корректное сообщение без замечаний.
4. Проверены понятные правила, проверочные/словарные слова и отказ от ложных
   подсчётов. Для качества реальной модели нужен отдельный живой пилот;
   подставной ответ API не доказывает лингвистическую точность.
5. Проверены manual/auto, отмена во время ожидания, дедупликация и MAM,
   ограничение объёма, отсутствие утечки исходного текста и изоляция пользователей.
6. Обычные тесты работают с временными данными и подставными API. Семейные
   сообщения для фикстур не копируются; сценарии пилота используются отдельно.
