# Эксплуатационный этап: обновление одной командой и автозапуск

Запрошен владельцем перед расписанием. Целевая версия — 0.3.3.
Языковые комментарии и расписание в этот этап не входят.

- После однократной установки выполнять `sudo goose-update`: загрузить main,
  зафиксировать SHA, подготовить отдельный неизменяемый venv с lock/hashes и
  проверить его до остановки действующего сервиса. Поддержать явный ref/SHA.
- Перед активацией остановить только Гуся, взять блокировку данных, создать
  защищённую согласованную копию SQLite, конфигурации, env, образа и unit.
  Проверить целостность копии и миграцию отдельной пробной копии новым кодом.
- Атомарно переключать активный venv, сохранять предыдущее окружение.
  После запуска проверять готовность XMPP нового процесса, а не только наличие PID.
  Не перезаписывать настройки, образ, режимы и ключи. Не запускать API модели.
- При ошибке возвращать старый код только при совместимых схеме и зависимостях.
  Действующую БД, особенно OMEMO, автоматически из копии не восстанавливать.
  Оставлять понятную диагностику, копию и восстанавливаемое состояние обновления.
- Защитить от параллельных обновлений и грязного checkout. При прерванном
  обновлении обнаруживать журнал операции; не продолжать молча поверх него.
  Ограничивать накопление только собственных окружений; копии данных не удалять.
- Включать сервис после успешного обновления и при загрузке ОС. Временные
  ошибки соединения повторять с паузой, ошибки настроек/авторизации не зацикливать.
  Перезагрузку VDS в живой приёмке не выполнять без отдельной команды владельца.
- Сохранённый auto возобновлять после полного MAM и Carbons. Намеренный manual
  сохранять. При временном таймауте удерживать подтверждённую позицию и паузу,
  затем автоматически возвращать прежний auto после успешной повторной проверки.
  Утраченная/недостоверная позиция требует явного решения владельца.
- Проверять офлайн: неудачная загрузка/сборка до остановки, копирование, миграция,
  переключение, ошибка запуска, совместимый/несовместимый откат, прерывание,
  блокировки, сохранность секретов, ключей и manual/auto. Проверить настоящий
  установленный wheel и старую установку без системных действий/сети XMPP.

Регулярные копии по расписанию — следующий небольшой этап на этой основе:
согласованная копия работающего хранилища, ротация и проверка восстановления.
В текущем этапе обязательна копия перед каждым изменением активной версии.
