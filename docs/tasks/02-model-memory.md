# Задача № 2: модель, учебная помощь и память

Основание: этап 2 [ROADMAP.md](../ROADMAP.md), разделы 3–9 [SPEC.md](../SPEC.md).

Реализовать внешний текстовый API через отдельный адаптер, редактируемый образ Гуся,
актуальный профиль и ограниченную историю каждого нормализованного bare JID.
Провайдер и реальная модель выбираются перед живым пилотом с владельцем;
разработка и автоматические проверки не используют реальные аккаунты и платные запросы.

Обязательный результат:

- HTTPS Chat Completions с фиксированным адресом из настроек, таймаутом,
  пределом ответа, ограниченными повторами, общей параллельностью и частотой запросов.
- Внешний файл образа, загружаемый для каждого нового запроса, и актуальный профиль
  из SQLite. Идентификаторы аккаунтов и расписания отдельно в API не передаются.
- Раздельные истории и режимы, очистка только собственного контекста,
  ограничение окна и срока хранения. Очистка не удаляет профиль и чужие данные.
- `!admin mode <bare_jid> [manual|auto]` только для владельца;
  `!context clear` — для собственного диалога разрешённого отправителя.
- Новый диалог в manual. Пауза, очистка и изменение профиля отменяют задания
  соответствующего диалога. Ревизия проверяется под его блокировкой непосредственно
  перед фактической постановкой зашифрованного ответа в XMPP-очередь.
- HTTP не блокирует обработку управляющих команд. Поздний результат после отмены,
  включая игнорирование отмены адаптером, не отправляется.
- Миграция схемы 1 → 2 сохраняет профили, OMEMO, доверие и дедупликацию;
  отказ миграции не оставляет частично обновлённую схему.
- Локальная диагностика без запросов к модели; только явный `doctor --api`
  делает один небольшой запрос с предупреждением о возможной оплате.

До MAM-синхронизации этапа 3 сохранённый auto после каждого подключения остаётся
на паузе до повторного явного подтверждения владельца. Это ограничение отражается
в статусе и инструкции. Старые задания после запуска не восстанавливаются.

Расписание, изображения, автоматический перехват ручной отправки, чтение MAM,
основной аккаунт и автоматическое обновление/откат остаются следующими этапами.
Пилот — на отдельном тестовом аккаунте с владельцем. Отчёт отдельно перечисляет
офлайн-проверки и ещё не выполненные живые сценарии.
