# Статистика API, 0.3.11

Учёт включается с новой версией для автоматических запросов из диалогов.
Новых дневных лимитов нет. Отдельные doctor --api, ручные диагностические
скрипты и другие приложения с тем же ключом в эту статистику не входят.
Прошлые расходы до начала учёта из переписки не восстанавливаются.

## Команды владельца

Отправлять из управляющего аккаунта в зашифрованный чат с Гусём:

```text
!admin usage
!admin usage month
!admin usage pupil1@example.org
!admin usage pupil1@example.org month
!admin usage all 2026-10-30
!admin usage pupil2@example.org 2026-10
```

Без аргументов — все аккаунты за сегодня. Только период — все за этот период.
Только bare JID — выбранный собеседник за сегодня. Ресурс в целевом JID
недопустим. Сводка all включает сохранённые данные прежних разрешённых аккаунтов;
адресная команда разрешена для текущих профилей allowlist. Обычному аккаунту
административная команда недоступна. Команды сами модель не вызывают.

Сводка показывает обращения, попытки API и повторы, попытки с пригодным
текстовым ответом, известные токены на входе/выходе и полноту usage. Текстовый
ответ API не означает доставку ребёнку: ручная отмена могла произойти позже.
Периоды считаются в timezone конфигурации, по времени начала каждой попытки.
Обращение с повтором через полночь может появиться в обоих дневных отчётах;
в месячной сводке call_id учитывается один раз. Попытки и токены суммируются.

## Оценка денег

Без тарифа выводятся только счётчики. Для оценки добавьте usage в config.toml.
Следующие числа **вымышленные**, их нужно заменить на свой действующий тариф:

```toml
[usage]
price_model = "gpt://FOLDER_ID/aliceai-llm-flash/latest"
currency = "RUB"
input_per_million = "100"
output_per_million = "200"
```

Обе цены указаны за миллион токенов. Если провайдер публикует цену за тысячу,
умножьте её на 1000. price_model должен совпадать с нужной моделью; текущий
llm.base_url определяет провайдера. Для другой модели или старого endpoint
денежная оценка не строится. Смена модели не переносит тариф автоматически.

Это оценка сохранённого известного объёма по **текущим** настройкам тарифа,
не исторический платёжный журнал. Изменение цен пересчитает оценку старых
запросов. Скидки за кэш, другие начисления и фактические правила округления
провайдера не моделируются; внутренние reasoning/cache детали не добавляются
повторно к итоговым токенам. Нельзя считать эту сумму счётом провайдера.
Для запроса без полных prompt/completion стоимость неизвестна; число таких
попыток и неподходящих моделей показывается отдельно.

## Сохранность и границы

SQLite схемы 6 хранит по попытке: случайные идентификаторы, JID, модель/endpoint,
начало/окончание, закрытый код исхода и доступные числа токенов. Тексты сообщений,
ответы API и ключи не записываются. Исходный диалог остаётся в прежней памяти,
команда clear не удаляет статистику.

Валидация usage следует Chat Completions: prompt_tokens, completion_tokens,
total_tokens. Проверены типы, неотрицательность, верхняя граница и согласованность.
Если известны обе составляющие, отсутствующий total вычисляется их суммой.
Частичные корректные данные сохраняются; отсутствие или неверные значения
не превращаются в нули и не мешают обычному ответу.
Контракт сверялся с [официальными OpenAPI-типами OpenAI](https://github.com/openai/openai-python/blob/main/src/openai/types/completion_usage.py).

До HTTP-попытки сохраняется запись; если это невозможно, новый платный запрос
не начинается. Неудача финальной записи не отнимает готовый ответ: остаётся
попытка с неизвестным расходом. После перезапуска незакрытые попытки помечаются
прерванными. При дальнейшей работе записи без завершения старше часа также
помечаются прерванными; поздние известные счётчики ещё могут дополнить такую запись.
Местный отказ по уже существующему минутному лимиту API-попыткой не считается.

При новых попытках удаляются завершённые записи старше 400 дней и сверх
100000 последних записей. Ещё не закрытые попытки защищены до завершения или
восстановления состояния. Если начало учёта или ротация затронули период,
сводка явно сообщает о неполном покрытии. Обычный журнал содержит только
api_usage_failed phase=start|finish без JID и текста исключения.

## Обновление и пилот

Установить проверенный SHA существующим goose-update. Он создаёт копию
и проверяет миграцию клона. Схема 5 повышается до 6; рабочие ключи, профили,
режимы, языковые настройки и расписание копирования сохраняются.
Старый код схемы 5 с новой БД несовместим; рабочая OMEMO-база автоматически
старым снимком не подменяется. Тариф можно оставить незаданным.

После установки запросить usage, отправить обычный новый вопрос, затем снова
запросить usage. Попытки должны появиться у нужного аккаунта, а не у другого;
команда сводки не добавляет новых запросов. Проверить month и просмотр обычным
неадминистратором. Перезапуск сервиса сохраняет статистику; VDS не перезагружается.
Проверить backup status и пробное восстановление отдельного клона.
