# Настройки и команды

Реализованы этапы 1–2: TOML, профили, диагностические команды, legacy OMEMO,
текстовый API модели, отдельная память и явные режимы. Расписание этапа 4 пока не поддерживается.

## Конфигурация приложения

Пример: [../config/config.example.toml](../config/config.example.toml). Реальная копия располагается вне Git, целевой путь — `/etc/goose-xmpp-bot/config.toml`.

В конфигурации задаются подключение XMPP, список разрешённых аккаунтов и администраторов, часовой пояс, включение модели и расписания, ограничения ресурсов и начальные профили. Неизвестные поля и неверные типы должны давать понятную ошибку; поля будущих этапов можно поддерживать как валидируемые неактивные настройки, но не игнорировать молча.

Пароль берётся из `xmpp.password_env` (по умолчанию `GOOSE_XMPP_PASSWORD`). Ключ модели —
из `llm.api_key_env` (по умолчанию `GOOSE_LLM_API_KEY`), только при включённой модели
и явном запуске сервиса/API-проверки. Файл окружения на VDS имеет ограниченные права.
Реальные секреты не передаются через сообщения боту.

Требования к валидации:

- TLS и проверка сертификата включены.
- Администраторы входят в allowlist; resource не меняет идентичность отправителя.
- Класс в начальной версии — целое число от 1 до 11; `academic_year` соответствует виду `YYYY-YYYY` с последовательными годами.
- Настроен существующий часовой пояс IANA.
- `schedule.enabled` должен быть `false`. `llm.enabled=false` по умолчанию; при включении
  обязательны HTTPS `base_url` без учётных данных/query и непустой `model` до 128 символов.
  Поддерживается `provider="openai_compatible"`; пустые адрес/модель допустимы при выключенной модели.
- Каталог данных расположен вне исходников, доступен сервису и имеет подходящие права.
- `diagnostics.echo_enabled` по умолчанию выключен; даже при включении команда доступна только владельцу.
- Неизвестные поля отклоняются. `runtime.default_mode` — только `manual` для нового диалога;
  auto включает владелец для конкретного собеседника. `log_level` — `INFO`, `WARNING` или `ERROR`,
  без XML-логирования. `runtime.max_attempts` (1–10, по умолчанию 3) ограничивает число XMPP-сессий
  за запуск; `connect_timeout` (5–120, по умолчанию 45) — время инициализации сессии.
  Стабильная сессия не ограничена этим временем. После исчерпания попыток сервис выходит;
  systemd не перезапускает его бесконечно.
- Начальные профили содержат все четыре поля. Их JID входит в allowlist; аккаунт бота в allowlist не включается. В конфигурации принимаются bare JID, а resource входящих сообщений удаляется средствами Slixmpp.
- Каталог данных имеет права `0700`, база — `0600`. База привязана к одному аккаунту. Для другого тестового JID нужен отдельный каталог данных.

## Модель и память

`persona_file` — абсолютный путь к непустому UTF-8 файлу до 8192 байт, по умолчанию
`persona.md` рядом с конфигом. Пример — [persona.example.md](../config/persona.example.md).
Файл читается заново для каждого запроса; актуальный профиль берётся из SQLite.

Шаблон задаёт Гуся, Гусика и Гусмана как имена одного добродушного хвастуна,
правителя Гусинландии. Байки об изобретениях остаются игрой: принцип работы
объясняется правильно, а при уточнении называется настоящий автор либо
объясняется неоднозначность авторства. Жалобы Папану — реплики в текущем
чате; образ не добавляет отправку уведомлений другим пользователям.

Шаблон образа просит отвечать обычным текстом без Markdown, HTML и LaTeX:
формулы вида `2x + 3 = 9` и `(a + b)/c` читаются без математического рендерера.
Это инструкция модели, а не преобразование готового ответа в коде.
Существующий внешний образ установщик сохраняет, поэтому при обновлении
добавьте это правило в него самостоятельно. Перезапуск сервиса не требуется;
правило применяется к следующим запросам.

| Параметр | По умолчанию | Диапазон/назначение |
| --- | --- | --- |
| `llm.timeout_seconds` | 30 | 1–120; сетевые операции и общий предел с учётом попыток |
| `llm.max_output_tokens` | 700 | 1–4096; `max_tokens` Chat Completions |
| `llm.max_concurrent_requests` | 2 | 1–8; общая параллельность по диалогам |
| `llm.requests_per_minute` | 12 | 1–120; фактические попытки, включая повторы, в скользящем окне |
| `llm.max_attempts` | 2 | 1–3; ошибки подключения и HTTP 429/502/503/504 |
| `memory.recent_messages` | 24 | 1–100; окно текущего диалога |
| `memory.context_token_budget` | 6000 | 256–65536; оценка по UTF-8 байтам с запасом |
| `memory.retention_days` | 30 | 1–365; удаление при старте и затем каждый час |

Токенизация выбранной модели ещё не проверена: оценка по байтам ограничивает контекст
консервативно, но не является точным счётчиком всех провайдеров. Старые сообщения
исключаются первыми; если даже правила и новый вопрос не помещаются, запроса к API нет.
Хранилище ограничено также 500 ходами на диалог. Срок удаления может превышать настройку
не более чем на час при работающем сервисе; выборка API всегда отсекает истёкшие записи.

Ответ API ограничен 64 КиБ и 4096 символами текста. Редиректы и инструменты модели
не исполняются. Read timeout и разрыв после отправки не повторяются автоматически:
провайдер мог уже выполнить запрос. Сообщения об ошибках — не чаще одного в минуту
на диалог. Денежный лимит отдельно настраивается у провайдера.

## Профили

Связка пользователя с классом хранится в SQLite. Начальные `users` из TOML используются для создания отсутствующих профилей; дальнейшие изменения базы не сбрасываются при перезапуске.

Два независимых поля:

| Поле | Пример изменения |
| --- | --- |
| `grade` | С 2 на 3 для уровня объяснений |
| `schedule_class_id` | Перепривязка к группе расписания, например после перехода в другую школу |

Отдельно меняется `academic_year`. Изменение этих полей не очищает память. Текущий профиль применяется при каждом новом запросе.

## Синтаксис команд

Все команды выполняются только от разрешённого отправителя. Префикс `!` позволяет посылать их обычным текстовым сообщением. Ответ на административную команду возвращается владельцу, а не в детский диалог.

Диагностический `!ping` возвращает `Га-Га-Га!`. Команда и ответ передаются с OMEMO.

| Команда | Кому доступна | Этап |
| --- | --- | --- |
| `!help` | Разрешённым пользователям | 1 |
| `!ping` | Разрешённым пользователям | 1 |
| `!echo <текст>` | Только владельцу на тестовом аккаунте, при явно включённой диагностике | 1 |
| `!admin status` | Владельцу | 1 |
| `!admin user show <bare_jid>` | Владельцу | 1 |
| `!admin user set <bare_jid> grade=3` | Владельцу | 1 |
| `!admin user set <bare_jid> academic_year=2027-2028` | Владельцу | 1 |
| `!admin user set <bare_jid> schedule_class_id=<id>` | Владельцу | 1 |
| `!admin mode <bare_jid> manual` | Владельцу | 2 |
| `!admin mode <bare_jid> auto` | Владельцу | 2 |
| `!context clear` | Пользователю для собственного контекста | 2 |
| `!schedule today` / `!schedule tomorrow` / `!schedule YYYY-MM-DD` | Пользователю для своего расписания | 4 |
| `!расписание сегодня` / `!расписание завтра` | Русские алиасы команды расписания | 4 |
| «Какие у меня завтра уроки?» | Пользователю, через проверенный инструмент | 4 |

Поле в `user set` выбирается из разрешённого списка; выражение не исполняется как Python, SQL или shell. Неизвестный пользователь и некорректное значение дают ошибку без частичного изменения профиля. Права проверяются программно до любых запросов к модели.

Для очистки через `!context clear` удаляются история и резюме именно отправителя. Справка объясняет, что очистка памяти бота не удаляет архивы на XMPP-сервере, устройствах и у провайдера.

## Начальные режимы

Новый диалог создаётся в `manual`. Режим сохраняется в SQLite; при каждом подключении
сервиса сохранённый auto получает отдельный признак паузы. До MAM-синхронизации этапа 3
его нужно повторно подтвердить командой владельца. `!admin mode <bare_jid>` без
последнего аргумента показывает режим и паузу. Настройки и перезапуск сами по себе
не возобновляют поставленный на паузу разговор.

manual, очистка контекста и изменение профиля отменяют ещё не отправленные задания
своего диалога. HTTP и шифрование выполняются без блокировки переключения режима;
перед отправкой проверяются режим, ревизия и срок задания. Не более 8 ожидающих
сообщений на диалог и 64 заданий суммарно; переполнение отбрасывается с техническим
кодом. После запуска старые задания не воспроизводятся.

Автоматический перехват по ручному исходящему сообщению появляется на этапе 3. Он ставит только этот диалог в `manual`. Возврат выполняется командой владельца; календарного таймера возврата по умолчанию нет.

## Диагностика

`doctor.sh` должен разделять проверки:

- По умолчанию: локальные версии, синтаксис конфигурации, права, доступность каталога данных и состояние сервиса.
- Явная XMPP-проверка: реальная авторизация тестовой учётной записи, TLS и обнаружение поддерживаемых расширений. При возможном конфликте с работающим ресурсом сообщает о нём и использует отдельный диагностический resource; проверка не регистрирует новое OMEMO-устройство.
- Явная API-проверка `doctor --api`: сообщает, что запрос может тарифицироваться;
  один запрос, максимум 16 выходных токенов, без повторов и печати ответа.
  Обычная диагностика запрос модели не делает.

Вывод не содержит секретов, полного содержимого сообщений, ключей устройств и приватных промптов.

Команды установки, `doctor`, просмотра устройств и доверия описаны в [INSTALLATION.md](INSTALLATION.md). Клиентская проверка — в [TESTING_XMPP.md](TESTING_XMPP.md).
