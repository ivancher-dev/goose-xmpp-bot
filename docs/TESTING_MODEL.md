# Живая приёмка этапа 2

26 октября 2026 года владелец подтвердил установку 0.2.0, миграцию SQLite
на схему 2, диагностический ping и успешный `doctor --api`.
Провайдер — Yandex AI Studio, модель — `aliceai-llm-flash/latest`,
Chat Completions через `https://llm.api.cloud.yandex.net/v1`.
После явного auto получен первый учебный ответ в диалоге владельца.
Полная клиентская матрица модели ещё не проверена; офлайн-тесты не заменяют пилот.
Начните с [INSTALLATION_STAGE2.md](INSTALLATION_STAGE2.md) и отдельного
тестового аккаунта; первичный собеседник — владелец с вымышленными вопросами.
Детские диалоги остаются в manual. Не перезагружайте VDS ради этих проверок.

Зафиксируйте локально SHA, версии, провайдера, модель и бюджет без ключей, JID,
текста запросов и ответов в публичном отчёте.

| Сценарий | Живая проверка |
| --- | --- |
| Установка сохраняет прежний ID/отпечаток и доверие, ping работает с выключенной моделью | частично: ping работает, схема 2 проверена; ID/отпечаток повторно не сравнивались |
| `doctor` не делает запросов; `doctor --api` явно делает один ограниченный запрос | обе команды успешно выполнены владельцем |
| Новый manual не вызывает модель; auto включается только командой владельца | частично: владелец включил auto, получен ответ; manual ещё не проверен |
| Ответ читается обычным текстом без Markdown/LaTeX | следующий ответ без видимых маркеров; математические формулы после правки ещё не проверены |
| Гусик/Гусман узнаются; байка об изобретении объясняет верный принцип и раскрывает реальное авторство при уточнении; жалоба Папану остаётся шуткой в чате | частично: черты появились, но автор раскрывается сразу и на свежем контексте; вариант с примером двух реплик ещё проверяется |
| Уточнение использует контекст своего диалога; другой профиль/история не попадают в ответ | не проверено |
| Изменённый класс применяется к новому ответу, история и второй профиль сохраняются | не проверено |
| Редактирование persona.md влияет на новый запрос без перезапуска | подтверждено владельцем: новые черты появились в следующем ответе |
| manual во время ожидания отменяет неотправленный ответ; второй диалог продолжает работу | не проверено |
| Очистка отменяет ожидающий ответ и удаляет только свою память | частично: команда принята и подтверждает сохранение профиля; фактическое удаление, отмена и изоляция ещё не проверены |
| Ошибка API понятна пользователю и не создаёт поток одинаковых уведомлений | не проверено |
| После подключения auto сохранён, но требует явного подтверждения; старые задания не отвечают | не проверено |
| Доставка и ответы OMEMO с обоих клиентов, отсутствие дублей/циклов | не проверено для модели |
| RSS/CPU/рост SQLite и влияние на другие службы на VDS | не измерено |

API-адаптер ограничивает фактические попытки общей частотой; это не денежный бюджет.
Расходы дополнительно ограничьте у выбранного провайдера. Приёмка разрешений
обычного аккаунта этапа 1 и оставшиеся транспортные сценарии перечислены в
[TESTING_XMPP.md](TESTING_XMPP.md); они не объявляются выполненными из-за тестов модели.
