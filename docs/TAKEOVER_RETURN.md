# Временный ручной перехват, 0.3.12

Если диалог был в auto, отправка с другого устройства Гуся временно уступает
его человеку. Через 60 секунд без новой ручной реплики auto возвращается.
Каждая новая ручная реплика начинает минуту заново; сообщения ребёнка,
повторные Carbons/MAM и собственные ответы сервиса срок не продлевают.
В работающем процессе интервал дополнительно проверяется монотонными часами,
чтобы перевод системного времени вперёд не сокращал минуту. Проверка срока
выполняется примерно раз в секунду; занятая сеть/архив могут отложить возврат.

Явная команда `!admin mode pupil1@example.org manual` остаётся постоянной.
Возврат из неё — `!admin mode pupil1@example.org auto`. Начальный manual
и manual, оставшиеся от старого кода, автоматически не меняются: происхождение
старой паузы нельзя достоверно восстановить.

## Настройки

В существующем блоке interaction config.toml:

```toml
[interaction]
takeover_timeout_seconds = 60
takeover_review_enabled = true
```

Не создавайте второй блок interaction, если он уже есть. Отсутствующие поля
получают эти значения по умолчанию. timeout 0 выключает возврат, иначе допустимо
5–3600 секунд. review false сохраняет возврат без дополнительной оценки.
Применение конфигурации — перезапуск только сервиса Гуся.

Возврат требует включённой модели и полного профиля, готового соединения,
Carbons и подтверждённого архива. После перезапуска пауза сохраняется,
но до успешной синхронизации auto не включается. Утраченная позиция архива
по-прежнему требует явного auto. Непрочитанная ручная реплика блокирует оценку
всей этой паузы: нельзя угадывать, дал ли человек ответ.

## Продолжение разговора

При начале живого перехвата запоминается последний живой вопрос; свободные
сообщения во время паузы добавляются к кандидатам. В текущем варианте
оцениваются до трёх последних сообщений не старше десяти минут. Сообщение
может оказаться благодарностью или утверждением — тогда отвечать не надо.
Архивные сообщения сами кандидатов не создают. Если пауза с живыми кандидатами
пережила перезапуск, архив может восстановить контекст для её оценки.

Кандидат с уже записанным ответом сервиса исключается до обращения к модели.
Для остальных модель получает сам вопрос и последующую переписку, включая
ручные ответы. При ясном содержательном ответе, явной просьбе отложить или
сомнении продолжения нет. При уверенном решении о неотвеченных вопросах
генерируется одно общее продолжение от имени Гуся с обычным образом и профилем.
Это семантическое решение модели: его качество требует живой проверки и оно
может ошибаться. При переполнении контекста ручные объяснения не отбрасываются
ради генерации — продолжение пропускается.

Новая свободная реплика делает прежнюю оценку неактуальной и получает обычный
ответ в auto. Новое ручное сообщение вновь уступает диалог человеку. Проверки
режима и поколения задания действуют перед API и перед отправкой, включая
ожидание шифрования. Уже отправленное сообщение отменить нельзя.

Оценка выполняется не более одного раза на завершённую паузу; её сбой
не создаёт цикл повторных проверок или служебное сообщение ребёнку. После
аварийного завершения в момент оценки продолжение может быть пропущено —
позднее повторение не отправляется. При перегруженной очереди auto возвращается,
но оценка пропускается. Для продолжения повторные языковые заметки и лайк
старого вопроса не создаются; обычные новые вопросы сохраняют эти возможности.

Оценка — отдельное учитываемое обращение к API; при продолжении добавляется
ещё одно обращение генерации. Действуют прежние минутные ограничения и
повторы адаптера. Новых дневных лимитов нет. Ни JSON оценки, ни вопросы,
ни JID не выводятся в обычный журнал. Пауза хранит только время, номера
кандидатов и признак читаемости; тексты берутся из прежней раздельной памяти.

## Обновление и пилот

Использовать существующий goose-update с проверенным SHA. Он делает копию
перед обновлением и мигрирует клон. Схема 6 повышается до 7; прежние профили,
языковые настройки, статистика, города, ключи и таймер копирования сохраняются.
Откат на код схемы 6 с новой рабочей БД недопустим; нельзя подменять живую
OMEMO-базу старой копией автоматически.

Живые сценарии проверяются последовательно:

1. Ручная отправка из auto → manual; ещё одна ручная реплика через 30 секунд
   продлевает минуту. После последней минуты тишины — auto и ответ новому вопросу.
2. Явный manual остаётся после минуты; явный auto возвращает работу.
3. Отменённый вопрос без объяснения получает одно продолжение после паузы.
4. Вопрос с понятным ручным объяснением или просьбой отложить не дублируется.
5. Новое сообщение во время оценки отменяет старое продолжение; соседний
   диалог независим. usage включает оценку и генерацию отдельно.
6. Перезапуск с активной паузой ждёт полного архива. backup status и пробное
   восстановление копии проверяются отдельно от рабочих данных.
