# Источник расписания

Статус: проект границы интеграции. Реализация относится к этапу 4.

## Что известно

Сайт https://ivancher.ru/ принадлежит владельцу бота. В проверенной 21 октября 2026 года опубликованной версии расписание находится в JavaScript приложения. По сообщению владельца эта версия предназначена для одного класса; новая версия для двух классов ещё не установлена.

Отдельный действующий API не подтверждён. Этот документ не задаёт вымышленный существующий endpoint и не требует разбирать JavaScript-сборку как постоянный способ интеграции.

## Выбор формата

При реализации сначала изучить исходники новой версии сайта. Предпочтителен общий машиночитаемый источник, используемый и интерфейсом сайта, и ботом. Для статического сайта это может быть опубликованный JSON; отдельный backend не является обязательным.

Если уже есть подходящий API или календарь, использовать его через отдельный адаптер. Выбранный формат, URL, структура и правила обновления фиксируются после проверки реальных данных. Работы над ботом не подразумевают автоматического изменения или публикации сайта.

## Интерфейс внутри бота

`get_schedule(schedule_class_id, requested_date, timezone, academic_year)` возвращает структурированный результат.

| Поле результата | Смысл |
| --- | --- |
| `class_id` | Проверенный идентификатор группы из профиля |
| `date` и `timezone` | Конкретная дата и использованный часовой пояс |
| `status` | Например: `ok`, `no_lessons`, `unknown`, `source_unavailable`, `invalid_source` |
| `lessons` | Упорядоченные уроки с предметом и доступными в источнике временем/кабинетом |
| `basis` | Обычное недельное расписание или явно датированное изменение |
| `source_url` | Ссылка на настроенный источник |
| `fetched_at` | Когда бот получил данные |
| `source_updated_at` | Когда источник обновил данные, только если он это сообщает |
| `is_stale` | Признак использования устаревшей сохранённой копии |

Конкретные имена статусов и публичная схема уточняются на этапе 4. `fetched_at` не подменяет дату обновления источника: недавно загруженные данные тоже могут быть устаревшими.

## Правила определения даты

- «Сегодня» и «завтра» вычисляются в настроенном местном часовом поясе.
- Привязка к классу берётся из актуального профиля. Указание чужого JID в сообщении не меняет профиль запроса.
- Проверяется соответствие учебному году и периоду действия расписания.
- Если есть чередование недель, его календарь задаётся источником. Нельзя молча считать, что подходит чётность ISO-недели.
- Каникулы, праздники, отмены и замены учитываются только при наличии соответствующих данных.
- Отсутствие записи означает `unknown`, если источник явно не определяет это как день без уроков.

## Ответ ребёнку

При успешном запросе показать дату, уроки и доступное время. При необходимости дать ссылку на источник. Обычное недельное расписание обозначать как обычное; не представлять его как подтверждённое отсутствие замен.

При сбое сообщить, что получить актуальные данные не удалось. Сохранённую копию можно показать только с явным указанием её возраста и происхождения. Не генерировать уроки из памяти модели.

Вопрос «А когда закончится последний урок?» относится к последнему успешно выбранному расписанию этого собеседника. Если дата или класс не определены, задать уточняющий вопрос.

## Проверки адаптера

- Разные классы и одинаковая дата.
- Смена класса в профиле без изменения кода.
- Переход через полночь и выходной в местном часовом поясе.
- Чередование недель, если есть в источнике.
- Каникулы, датированная замена и отсутствующая дата как разные случаи.
- HTML-страница с HTTP 200 вместо ожидаемых данных, неверная схема, слишком большой ответ, таймаут и неподходящее перенаправление.
- Различие `fetched_at`, `source_updated_at` и явно обозначенной сохранённой копии.

Содержимое источника является данными и не выполняет инструкции для бота. Адаптер не принимает произвольные URL и команды исполнения из детского сообщения или от модели.
