# Отчёт 0.3.14: погода и уведомления

Реализован [запрошенный этап](tasks/02b-weather-resilience-alerts.md):
последовательный пул Open-Meteo/wttr.in, настройка 1–3 ежедневных сводок,
местный часовой пояс города, приветствия и простые советы из погодных фактов.
Утро 08:00, день 13:00, вечер 18:00; свои часы и отключение — командами.
По выбору владельца рассылка работает и в manual, без вызова модели.

Новый набор подписки полностью заменяет прежний. Настройки разделены по bare JID;
чужую подписку меняет только владелец. Отправка использует прежний OMEMO-транспорт.
Смена города/подписки или отключение отменяет ещё не отправленную старую сводку.
SQLite 7 → 8 сохраняет данные и добавляет подписки/отметки попыток.

## Автоматические проверки

- Итоговый полный прогон: 803 теста прошли. Отдельно прошли 41 новая проверка
  пула/рассылки и 174 целевые проверки погоды и транспорта.
- Проверены HTTP/сеть/таймаут, HTML с HTTP 200, неверные и старые данные,
  перенаправление и размер; оба порядка источников, кэш и восстановление приоритета.
- Проверены 1–3 слота/свои часы, город/timezone, разные пользователи, права,
  manual, перезапуск без повтора, опоздание, обрыв, DST, отмена во время шифрования,
  выключение и остановка. Общий транспорт отдельно проверен на исключение только
  плановой погоды из отмены по смене режима; шифрование и holds сохраняются.
- Временная БД схемы 7 мигрирует до 8 с сохранением синтетических ключей/города.
  Пробное SQLite-восстановление сохраняет подписку и защиту от повторной попытки.
- Реальные OMEMO-тесты и проверки копирования входят в полный прогон;
  сеть в обычных тестах запрещена, HTTP/XMPP подставные.

- Настоящий `goose-update` отдельной временной установки 0.3.13 → 0.3.14:
  схема 7 → 8; прежние таблицы, ключи, конфиг/env/образ, статистика и таймер
  сохранены. Установленный wheel при отказе Open-Meteo получает wttr.in,
  формирует одну утреннюю сводку с зонтом/шапкой в manual через подставной
  транспорт; повторная проверка не отправляет вторую. Новая копия содержит
  подписку и отметку; пробное восстановление старой и новой копий успешно.
- `pip check`, `compileall`, shell, TOML, внутренние ссылки и `git diff --check`
  успешны. Зависимости сохранены. GitHub Actions новой ветки пока не запускались.

## Границы

Живые погодные API, VDS, таймерная отправка в настоящие Gajim/Conversations
в этом этапе пока не проверены. Погодный пул имеет два независимых сервиса;
доступность второго с VDS нужно подтвердить. Геокодер один.
Нет гарантии доставки при общем отказе сети. Отметка перед отправкой защищает
от повторов ценой возможного пропуска при аварии. Опоздание ограничено 10 минутами.
Дневные минимум/максимум ветра не доказывают одновременный холод и ветер;
советы сформулированы условно. Прогноз остаётся на сутки, не только на остаток дня.

API не менялись: [Open-Meteo OpenAPI](https://github.com/open-meteo/open-meteo/blob/main/openapi/forecast.yml),
[контракт wttr j1](https://github.com/chubin/wttr.in#json-output).
[Команды, обновление и сценарии живого пилота](WEATHER_ALERTS.md).
